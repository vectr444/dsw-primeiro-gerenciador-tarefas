# Aula 04 — Protegendo Rotas com JWT e Isolamento de Usuários (06/10/2026)

## ✅ O que eu aprendi

Nesta aula usei o token JWT do login para trancar as rotas de tarefas e isolar cada usuário, de modo que cada pessoa veja e modifique apenas as suas próprias tarefas. As principais mudanças foram:

- Interface AuthRequest: estende o "Request" do Express com o campo opcional "usuarioId".
- Coluna usuario_id: adicionada na tabela "tarefas", com FOREIGN KEY para "usuarios".
- Middleware "authenticate": valida o header "Bearer <token>" com jwt.verify e injeta o id em "req.usuarioId". Sem token válido, retorna 401 e a rota nem executa.
- Isolamento nas consultas: todos os statements de tarefas filtram por "usuario_id". Mexer na tarefa de outro usuário afeta zero linhas e retorna 404.
- Rotas trancadas: "authenticate" aplicado em GET, POST, PUT, PATCH e DELETE de /api/tasks.

Também atualizei o resquests.http com a variável @token, o teste 3B (sem token, deve retornar 401) e o header Authorization nos testes de tarefas existentes. Testei com dois usuários: o B vê a lista vazia e recebe 404 ao tentar alterar ou apagar a tarefa do A.

## 🧩 Principal dificuldade
O editor acusou dois erros de TypeScript que o guia não menciona: o "verbatimModuleSyntax" do tsconfig exige importar Request, Response e NextFunction como tipos, e ao tipar o "req" como AuthRequest o "req.params.id" virou "string | string[]", que a "parsearId" não aceitava. Além disso, o banco antigo deixou de servir, pois o CREATE TABLE IF NOT EXISTS não altera tabelas existentes.

## 🔧 Como eu resolvi
Troquei o import por "{ type Request, type Response, type NextFunction }" e fiz a "parsearId" aceitar "string | string[]", retornando null quando não for string. Para o banco, em vez de apagar, renomeei o tarefas.db para tarefas.db.bak e subi o servidor para recriar a tabela.

## 💡 Observações (opcional)
Para testar é preciso fazer login (teste 38) e colar o token em @token; ele expira em 2 horas. O usuário admin da inicialização ainda é inserido com senha sem hash, então o login dele não funciona (já era assim antes).
