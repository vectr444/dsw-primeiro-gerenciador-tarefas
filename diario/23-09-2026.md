# Aula 03 — Adicionando Autenticação e Segurança (23/09/2026)

## ✅ O que eu aprendi

Nesta aula o foco foi implementar um sistema de registro e login de usuários com segurança. As principais mudanças foram:

- Instalação de duas novas dependências: "bcryptjs" para criptografia de senhas e "jsonwebtoken" para geração de tokens de acesso.
- Interface Usuario: Criação do molde tipado para os dados do usuário (id, email, senha).
- Tabela usuarios com UNIQUE: Adicionei a constraint UNIQUE na coluna de e-mail para impedir cadastros duplicados direto no banco de dados.
- Prepared Statements de autenticação: Criei "stmtBuscarUsuarioPorId" e "stmtBuscarUsuarioPorEmail" para consultas de usuário.
- Rota de Registro (POST /api/auth/register): Valida e-mail e senha (mínimo 6 caracteres), gera o hash com bcrypt antes de salvar, e trata duplicidade de e-mail retornando 409.
- Rota de Login (POST /api/auth/login): Compara a senha com o hash usando bcrypt.compareSync, usa um hash falso quando o usuário não existe para evitar timing attacks, e gera um token JWT com expiração de 2 horas.

Também adicionei os testes 35 a 39 no resquests.http para validar registro, senha curta, e-mail duplicado, login com sucesso e login com senha incorreta.

## 🧩 Principal dificuldade
Foi necessário apagar o arquivo tarefas.db e recriar o banco do zero, porque o comando CREATE TABLE IF NOT EXISTS não aplica alterações em tabelas já existentes — a constraint UNIQUE no e-mail não seria aplicada sobre o banco antigo.

## 🔧 Como eu resolvi
Parei o servidor, deletei o arquivo tarefas.db da pasta do projeto e rodei "npm run dev" novamente para que o banco fosse recriado com a nova estrutura.
